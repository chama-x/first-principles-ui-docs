Stress-Test Layouts Against Worst-Case Data

Inject adversarial 255-character strings, unbroken CJK text, and large numbers to expose flex squishing, avatar distortion, and ink clipping before shipping.

Why this works

Add shrink-0 to avatars and min-w-0 truncate to text columns to survive long names.

shrink-0 · min-width: 0 · truncate · Aspect w/h >= 0.90

Unbounded flex containers collapse avatars into slivers and blow out layouts when fed real adversarial data. Add shrink-0 to circular media and min-w-0 truncate to text labels so geometry never deflates under 255-character inputs.

Interfaces designed exclusively against kind mock data ("Alex Morgan", "Pro Plan", "$19/mo") inevitably fail in production. Real-world databases contain 255-character names, localized compound words, unbroken email addresses, and 8-figure account balances.

The Mathematical Invariant

In CSS flexbox and CSS grid layouts, elements default to min-width: auto rather than min-width: 0. When a text container contains long, unbroken strings, the browser expands the text element beyond its territorial container boundaries, squishing neighboring avatars and icons down to zero width or elliptic aspect ratios.

LAW_27_STRESS_DATA_CONTAINMENT enforces that under automated boundary data injection:

  1. Avatar Aspect Ratio Invariant: Any circular or square media container (img, svg, [data-avatar]) must satisfy: 0.90 <= w / h <= 1.10
  2. Ink Containment Invariant: The container element must satisfy: scrollWidth - clientWidth <= 3px

Implementation Pattern

Always pair flex siblings with defensive CSS tokens:

// Right: Defensive containment
<div className="flex items-center gap-3">
  {/* Circular avatar protected against deflation */}
  <img className="size-10 shrink-0 rounded-full object-cover" src={avatarUrl} alt="" />
  
  {/* Text parent container with explicit min-w-0 */}
  <div className="min-w-0 flex-1">
    <p className="truncate text-sm font-semibold">{user.name}</p>
    <p className="truncate text-xs text-muted-foreground">{user.email}</p>
  </div>
</div>

What to Look For & How the Linter Fixes It

Visual signs in your UI and how the verifier guides your coding agent.

Visual Symptom
  • Avatars squish into vertical slivers or ellipses when a user has a long name.
  • Long emails or URLs blow out parent card containers and cause horizontal page overflow.
  • Buttons and badges clip off the right edge of cards on narrow containers.
  • Layout breaks in production with real customer names after passing demo tests.
Linter Check
  • Avatar or thumbnail aspect ratio w/h < 0.90 or > 1.10 under stress.
  • scrollWidth - clientWidth > 3px container ink overflow.
  • Forward Oracle: ./check-ui-math.mjs calc stress-data --component Card
