Prevent Overlapping Text & Broken Ellipsis Truncation

Preventing direct text ink collisions, glyph overlap, uncontained text bleeding, and broken inline ellipsis truncation across responsive containers.

Why this works

Add min-w-0 and truncate to flex text children, and shrink-0 to status badges.

Gap >= 12px · Overlap = 0px

Absolute positioning causes badges and filenames to collide, bleeding letterforms together. Wrap flex siblings with min-w-0 and gap-3 so element bounding boxes remain strictly disjoint (Delta_overlap <= 0px) with zero ink collision.

Balanced Text Wrapping & Preventing Orphans

Interactive Drills

Few visual errors degrade interface quality faster than overlapping text nodes. When titles collide with badges, or when text-overflow: ellipsis is placed on an uncontained inline span, glyphs render directly over adjacent controls.

The substrate foundation is Geometric Spatial Disjointness:

  1. Topological Disjointness: Distinct typographic and interactive elements must represent disjoint spatial subsets: Area(A ∩ B) = 0.
  2. Ellipsis Containment: In CSS, text-overflow: ellipsis has no effect on display: inline elements unless paired with a block or inline-block container with overflow: hidden and min-w-0.

For multi-line headings and toasts, modern CSS provides text-wrap: balance and text-wrap: pretty. These eliminate awkward single-word typographic orphans and balance line lengths harmoniously:

Remediation

Wrap flexible text in flex containers with min-w-0 and truncate:

// Right: Safe flex containment
<div className="flex items-center justify-between gap-3 min-w-0">
  <span className="truncate min-w-0 font-medium">
    Long Dynamic Filename That Truncates Safely.pdf
  </span>
  <span className="shrink-0 rounded-full px-2 py-0.5 text-xs bg-muted">
    Badge
  </span>
</div>

The verifier extracts bounding ink boxes for all text lines, badges, and controls, detecting pairwise overlap:

Ink Overlap Threshold: Overlap_px <= 1.5px (zero allowable ink intersection) Inline Truncate Noop: text-overflow: ellipsis prohibited on display: inline without block formatting context.

// Evaluated by src/rules/ink-disjointness.mjs
const overlap = Math.max(0, Math.min(boxA.right, boxB.right) - Math.max(boxA.left, boxB.left));

if (isSameLine && overlap > 1.5) {
  ctx.report("LAW_19_TEXT_INK_COLLISION", {
    property: "horizontal_ink_overlap_px",
    computed: Math.round(overlap),
    threshold: 1.5,
  });
}

What to Look For & How the Linter Fixes It

Visual signs in your UI and how the verifier guides your coding agent.

Visual Symptom
  • Filenames, titles, or tags collide directly with action buttons or badges on the same line.
  • Adding truncate to an inline span fails to truncate and causes text to bleed out of the card.
  • Headlines leave an awkward single word hanging on the final line (orphans).
Linter Check
  • Horizontal ink bounding box overlap > 1.5px between text and sibling nodes.
  • scrollWidth - clientWidth > 3px uncontained ink overflow.
  • text-overflow: ellipsis applied to display: inline element.

Agent Prompts & Oracles

Plug directly into Claude, Codex, or terminal execution.

Build a responsive list item with title, status pill, and action menu. Structure the title with flex-1, min-w-0, and truncate to guarantee pairwise geometric disjointness (zero ink overlap with status pills). Use text-wrap: balance on multi-line headers to prevent typographic orphans.
