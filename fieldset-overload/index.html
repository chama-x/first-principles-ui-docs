Chunk Long Forms Into Digestible Steps

Bounding contiguous form inputs per fieldset (<= 5 inputs) to prevent cognitive fatigue, visual overwhelm, and form abandonment.

An endless single-page form with 8 raw inputs causes cognitive fatigue and form abandonment. Chunk complex inputs into logical steps of <= 5 fields each, preserving momentum with progressive forward disclosure.

Long, unbroken forms trigger immediate visual fatigue and abandonment. When an interface presents 8 to 12 unstructured input fields without conceptual separation, the user's working memory cannot chunk the requirements into achievable sub-tasks.

The substrate principles stem from Cognitive Load Theory and Working Memory Chunking:

  1. Subitizing Threshold in Forms: Humans can comfortably parse up to 4–5 coherent inputs as a single conceptual cluster (e.g., Shipping Address or Payment Credentials).
  2. Perceived Task Cost: When an undivided form exceeds 5 inputs, the visual complexity triggers an avoidance reaction, sharply degrading completion velocity.
  3. Progressive Disclosure: Forms requiring more than 5 inputs must partition controls into multi-step wizards or clearly delineated sequential fieldsets.

Remediation

Partition long forms into semantic fieldsets with concise <legend> titles or tabbed wizard steps:

// Right: Chunked into distinct fieldsets (<= 4 inputs each)
<form className="space-y-6">
  <fieldset className="space-y-3 rounded-xl border border-border/80 p-4">
    <legend className="text-xs font-semibold px-1">Account Credentials</legend>
    <input className="input" placeholder="Work Email" />
    <input className="input" type="password" placeholder="Password" />
  </fieldset>

  <fieldset className="space-y-3 rounded-xl border border-border/80 p-4">
    <legend className="text-xs font-semibold px-1">Company Profile</legend>
    <input className="input" placeholder="Company Name" />
    <select className="select"><option>Team Size</option></select>
  </fieldset>
</form>

The verifier traverses every <fieldset> and [data-form-group] container, tallying all visible non-hidden form controls:

Fieldset Subitizing Cap: Inputs_visible <= 5 where Inputs_visible = sum(input[type != hidden] + select + textarea)

View Deterministic Verifier Source (check-ui-math.mjs)

// Evaluated by src/rules/fieldset-overload.mjs
const maxInputs = config.density.maxFieldsetInputs; // 5

for (const fs of fieldsets) {
  const inputs = Array.from(
    fs.querySelectorAll('input:not([type="hidden"]), select, textarea')
  ).filter(helpers.isVisible);

  if (inputs.length > maxInputs) {
    ctx.report("LAW_02_FLOW_FIELDSET_OVERLOAD", {
      property: "inputs_per_fieldset",
      computed: inputs.length,
      threshold: maxInputs,
    });
  }
}

What to Look For & How the Linter Fixes It

Visual signs in your UI and how the verifier guides your coding agent.

Visual Symptom
  • A checkout or settings form is a long, undivided wall of 12 input boxes.
  • Form conversion rates drop because users feel overwhelmed upon seeing the entire form.
  • Inputs lack logical grouping into coherent steps (e.g. Account, Shipping, Payment).
Linter Check
  • More than 5 visible form controls (input, select, textarea) in a single <fieldset> or [data-form-group].

Agent Prompts & Oracles

Plug directly into Claude, Codex, or terminal execution.

Build a multi-step user onboarding and checkout form. Chunk inputs into distinct semantic <fieldset> groups with at most 4–5 controls each (e.g., Step 1: Personal Details, Step 2: Shipping Address, Step 3: Payment). Use progressive disclosure to reveal steps sequentially.
