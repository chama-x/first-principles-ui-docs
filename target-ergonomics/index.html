Touch Target >= 36x36px (Desktop) · >= 44x44px (Mobile)

Buttons smaller than 36px trigger missed taps, accidental clicks, and motor frustration under Fitts's law. Expand interactive touch targets to at least 44x44px on mobile and 36x36px on desktop with invisible pseudo-element padding.

Target Expansion & Hit Area Ergonomics

Interactive Drills

Tiny interactive buttons cause mis-taps, frustration, and increased motor effort. On touchscreens, tapping a 20px icon button without sufficient padding often triggers adjacent controls. On mobile browsers, tapping an input styled with a 13px font forces the viewport to violently zoom in, disorienting the user.

  1. Fitts's Law: Acquisition time MT = a + b log2(1 + D/W) is inversely proportional to target width W. When W drops below fingertip contact pad dimensions (~7mm / 36px), error rates spike exponentially.
  2. Compact Toolbar Exceptions: Inside high-density toolbars or compact table action rows, targets may compress to 28x28px provided they have sufficient spacing to avoid accidental activation.
  3. Mobile Auto-Zoom Floor: iOS Safari and WebKit automatically zoom into any focused <input>, <select>, or <textarea> whose computed font-size is under 16px. This shifts the entire page layout and requires users to manually pinch-to-zoom back out.

Hit Area Expansion via Invisible Pseudo-Elements

When visual design calls for a compact 20px icon, you do not need to bloat the visible button frame. An invisible ::after pseudo-element can expand the touch hit area to 36x36px or 44x44px while keeping the icon visually delicate:

The verifier measures bounding boxes of all interactive targets and checks computed font sizes on mobile:

Standalone Target Size: min(Width, Height) >= 36px (>= 28px in toolbars) Mobile Input Font Size Floor: font_size >= 16px (prevents iOS Safari auto-zoom)

View Deterministic Verifier Source (check-ui-math.mjs)

// Evaluated by src/rules/target-ergonomics.mjs
const minTarget = inCompactZone ? 28 : 36;
const r = btn.getBoundingClientRect();

if (r.width < minTarget || r.height < minTarget) {
  ctx.report("LAW_07_FITTS_TARGET_SIZE", {
    property: "min_dimension_px",
    computed: Math.round(Math.min(r.width, r.height)),
    threshold: minTarget,
    operator: ">=",
  });
}

if (vpConfig.isMobile && inputFontSize < 16) {
  ctx.report("LAW_18_IOS_INPUT_ZOOM", {
    property: "mobile_input_font_size_px",
    computed: inputFontSize,
    threshold: 16,
    operator: ">=",
  });
}

What to Look For & How the Linter Fixes It

Visual signs in your UI and how the verifier guides your coding agent.

Visual Symptom
  • Users frequently miss or accidentally double-tap small 20px icon buttons.
  • Tapping a form input on iPhone causes Safari to violently zoom in, breaking the page layout.
  • Buttons in dense toolbars overlap each other's touch hit areas.
Linter Check
  • Standalone interactive control min(w, h) < 36px (or toolbar < 28px).
  • Mobile input font-size < 16px (triggers WebKit auto-zoom).

Agent Prompts & Oracles
