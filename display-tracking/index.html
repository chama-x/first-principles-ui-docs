Optical Tracking Scale & Uppercase Spacing

Interactive Drills

When digital type scales up to display sizes (34px and beyond), the default proportional font metrics create excessive inter-glyph whitespace. Words appear dispersed and optically weak. Conversely, body copy that spans too wide forces readers to make disorienting eye movements.

  1. Optical Tracking Inversion: In metal typesetting, smaller text sizes required wider spacing to remain legible, while large display type was kerned tighter. Modern digital fonts use linear scaling by default; headings >= 34px must tighten letter-spacing by -0.025em to -0.04em to maintain cohesive word shapes.
  2. Saccadic Return-Sweep Ergonomics: When reading, human eyes move in rapid jumps (saccades) followed by a return-sweep to the start of the next line. If a paragraph exceeds 36em (~65–70 characters), readers consistently land on the wrong line, causing cognitive re-reading fatigue.
  3. Uppercase Widening vs. Display Tightening: While large mixed-case headings require negative tracking, small uppercase labels (e.g. badges or table headers) require positive tracking (letter-spacing: 0.05em to 0.1em) to offset optical clumping:

Under the Hood: Mathematical Formula & Verifier SourceOptional Deep Dive

The verifier checks display headings, prose paragraphs, and typographic orthography:

Continuous Optical Tracking Curve: tau(s) = clamp(-0.045em, -0.022 * ln(s / 16)em, +0.025em)
Continuous Hyperbolic Leading Curve: lambda(s, M) = clamp(1.02, 1.02 + 8.5 / s + 0.003 * max(0, M - 55), 1.75)
Display Tracking (>= 34px): letter-spacing <= -0.025em (tightened optical cohesion)
Prose Line Measure: Width / font_size <= 36em (~65–68 characters per line)
Sentence-Case UI & Hygiene (LAW_33): Sentence case on UI controls >= 14px, uppercase strictly on 10–13px eyebrows with +0.06em tracking, zero decorative AI emojis.

// Evaluated by src/rules/display-tracking.mjs
for (const item of textElements) {
  const { el, cs, fs } = item;

  // 1. Display Optical Tracking (>= 34px)
  if (fs >= 34) {
    const trackingEm = (parseFloat(cs.letterSpacing) || 0) / fs;
    if (trackingEm > -0.025) {
      ctx.report("LAW_13_DISPLAY_TRACKING", {
        property: "letter-spacing",
        computed: `${trackingEm.toFixed(3)}em`,
        threshold: "-0.025em",
        css_patch: { "letter-spacing": "-0.03em" },
      });
    }
  }

  // 2. Prose Measure (<= 36em)
  if (el.tagName === "P" && el.getBoundingClientRect().width / fs > 36) {
    ctx.report("LAW_13_PROSE_MEASURE", {
      property: "paragraph_measure_em",
      threshold: 36,
    });
  }
}

What to Look For & How the Linter Fixes It

Visual signs in your UI and how the verifier guides your coding agent.

Visual Symptom
  • Large display headlines (> 34px) appear loose, dispersed, and optically disconnected.
  • Paragraphs stretch across the entire widescreen monitor, making reading line-swaps disorienting.
  • Small uppercase labels look cramped because uppercase tracking wasn't widened.
  • UI controls contain ALL-CAPS shouting, raw ASCII dashes, or decorative AI emojis.
Linter Check
  • Display heading (>= 34px) letter-spacing > -0.025em.
  • Paragraph element measure width / font-size > 36em (~65ch).
  • All-caps controls >= 14px, raw ASCII dashes/ellipses, or AI emojis.

Agent Prompts & Oracles

Plug directly into Claude, Codex, or terminal execution.
